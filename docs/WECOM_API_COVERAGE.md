# 企业微信接口中心（全量接口接入）

系统管理 → 企业微信接口：`/admin/wecom-api`。把官方服务端 API 做成可检索、可配置凭证、可在线调用、可审计的统一入口，管理员不需要改代码就能验证和补齐企微能力。

## 一、接入范围

## 二、八类凭证

企业微信按能力发不同的 Secret，只有自建应用的 Secret 调不了客户联系、打卡、微信客服。

| 凭证 | 配置项 | 覆盖接口 | 在企微后台哪里拿 |
|---|---|---|---|
| 自建应用 | `WECOM_SECRET` | 消息、审批、汇报、日程、会议室、文档、素材、应用管理 | 应用管理 → 聚成工作台 → Secret |
| 通讯录同步 | `WECOM_CONTACTS_SECRET` | 成员/部门/标签的创建、更新、删除、全量同步 | 通讯录同步助手 → Secret |
| 客户联系 | `WECOM_EXTERNAL_SECRET` | 客户、客户群、朋友圈、群发、离职继承 | 客户联系 → 客户 → API Secret |
| 微信客服 | `WECOM_KF_SECRET` | 客服账号、接待人员、会话分配、消息收发 | 微信客服 → 开发 → Secret |
| 打卡 | `WECOM_CHECKIN_SECRET` | 打卡规则、记录、日报月报、排班、补卡 | 打卡应用 → Secret |
| 会议 | `WECOM_MEETING_SECRET` | 预约会议、会中控制、录制 | 会议应用 → Secret |
| 文档与微盘 | `WECOM_DOC_SECRET` | 文档内容、空间与文件 | 文档/微盘应用 → Secret |
| 群机器人 | `WECOM_WEBHOOK_KEY` | 群消息推送 | 群设置 → 群机器人 → Webhook 地址里的 key |

凭证保存在服务器 `integrations.json`（`0600`），不入库、不进审计、不回显；页面只显示尾号。接口调用时按目录默认凭证取 token，也可在单次调用里改选。token 按凭证分别缓存，配置变更后自动失效。

## 三、三条使用路径

1. **接口中心**：选大类 → 选接口 → 填查询参数和 JSON 包体 → 调用。写操作（POST）必须二次确认；响应超过 256KB 只展示前 200 条；每次调用记录接口、结果、耗时，不存报文原文。
2. **业务代码**：`Gateway.call(凭证, 方法, 路径, params, json)`；错误以 `WeComApiError(errcode, errmsg)` 抛出，token 失效与频控已内置重试。
3. **接口复用**：目录里的 `permission` 字段保留了官方权限说明，写操作按 `credential_for()` 自动落到正确凭证，避免用错 Secret 导致 `60011`/`48002`。

## 四、仍然需要企业侧条件的接口

代码侧已经能调到，但企业没开通对应能力时平台会返回权限错误，属预期：

- **会话内容存档**：要单独购买并开启「会话内容存档」，且必须用官方 SDK（C/Java/Python）拉取，不能只靠 HTTP。目录里 5 个是配置类接口。
- **企业支付 / 对外收款**：需要商户号、API 证书与密钥，不是应用 Secret。
- **家校沟通 / 政民沟通**：只有学校、教育局、政府单位类型的企业才有对应通讯录与接口权限。
- **客户联系**：需要在企微后台开通「客户联系」并把成员加入使用范围。
- **打卡**：需要开通打卡应用并单独拿 Secret；工作台现有考勤仍以导出 Excel 上传为主，接口已可调用，页面尚未切换。
- **会议**：部分高级能力（Rooms、MRA、 webinar）要求企业已开通会议高级功能。
- **工作台自定义展示**：接口已收录，但需要应用已发布且管理员同意模板变更才会生效。

## 五、业务接线：审批提交 / 打卡 / 客户联系

接口中心解决“能不能调”，下面三条链路已经接到具体页面，日常不用再进接口中心。

### 1. 审批提交（报销、合同）

- 入口：报销归集页「发起企微报销」、合同详情页「发起合同审批」。
- 配置：接口中心「审批模板」填写模板 ID（存 `sys_dict(wecom_approval/templates)`），模板可用控件由 `oa/gettemplateinfo` 实时读取，不需要在代码里写死字段。
- 提交：按控件标题匹配值，支持 Text / Textarea / Number / Money / Date / Selector / Contact；`oa/applyevent` 用模板自带审批人（`use_template_approver=1`）。必填项缺失会逐项列出，不会静默丢字段。
- 合同页会自动带出客户名称、合同名称、金额、签订日期、项目、负责人；报销页由申请人填写。
- 限制：附件、明细表控件暂不支持，需在企微客户端补充；审批结果仍由既有回调/对账同步回工作台。

### 2. 打卡记录（替代手工导出 Excel）

- 入口：人事中心 → 考勤核对 →「从企业微信拉取」。
- 实现：`checkin/getcheckindata`（原始打卡，按 100 人分批）× 按人按日聚合为上班/下班，写入与 Excel 导入完全相同的明细表，再走同一套判定规则、汇总与汇总表导出。
- 覆盖：同一期间重复拉取会覆盖原明细；没有打卡的成员计入 skipped。
- 限制：打卡接口不含请假审批，请假仍需审批同步或人工补录；首次使用需配置「打卡」Secret，并在企微后台开通打卡应用。

### 3. 客户联系（市场部商机）

- 入口：商机信息页「企业微信客户」。
- 实现：`externalcontact/get_follow_user_list` 取可服务客户的成员，`externalcontact/batch/get` 分页取客户（姓名、企业、备注、标签）；「登记商机」把客户名称带入新增商机表单，并在备注里保留 external_userid 便于回溯。
- 权限：只对市场 / 商机菜单开放，只读、不落库。
- 限制：需配置「客户联系」Secret，并在企微后台把成员加入客户联系使用范围。

## 六、刷新目录

```bash
cd backend
.venv/bin/python -m scripts.refresh_wecom_catalog            # 全量抓取，约 2 分钟
.venv/bin/python -m scripts.refresh_wecom_catalog --method-cache /tmp/apifox_methods2.json
```

脚本会重写 `catalog.json`，不改数据库。刷新后重启 API 即可生效（目录在进程内缓存）。
