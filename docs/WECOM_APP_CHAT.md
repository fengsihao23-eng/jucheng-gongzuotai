# 企业微信应用内对话与智能上传（2026-10 第二期）

同事不用打开浏览器：在企业微信「聚成工作台」应用里直接发消息、点底部菜单，就能问小聚、查知识库、交资料。

## 一、应用里能做什么

| 同事的操作 | 系统怎么处理 | 回复 |
|---|---|---|
| 发文字（如「这个月新签了多少合同」） | 以本人账号权限交给小聚办理，同一成员固定一个「企业微信对话」，上下文连续 | 先回「收到，正在处理…」，办完回复结果；需要确认的写操作附「打开工作台确认」链接（直接打开小聚页面的这段对话），不在聊天里直接提交 |
| 发「搜 年休假」「知识库 报销」 | 直接检索知识库（按本人可见范围） | 前 3 条结果和出处链接 |
| 发「帮助」「?」「你好」 | — | 使用说明 |
| 发图片 | 下载后进入「资料导入」（来源标记为企业微信），一般进待整理池 | 文本卡片：去向和下一步 |
| 点菜单「上传资料」「知识库」「工作台」 | 打开对应网页，企业微信内自动登录 | — |
| 点菜单「我的导入进度」「待我审核」 | — | 最近 5 条导入状态 / 待审核文档清单 |
| 发语音、视频、位置、链接 | 不处理 | 提示改发文字或用菜单 |

- 小聚不可用（模型或执行核心没就绪）时，文字消息自动改为检索知识库。
- 小聚回复超过 600 字会截断，并提示在工作台查看全文。
- 只处理已绑定公司通讯录的有效成员；没开通的成员会收到「还没有开通」的提示。
- 企微回调会重试，所以每条消息按 `MsgId` 只处理一次。表 `sys_wecom_inbound` 只存前 200 字摘要和处理结果，不存全文。

**关于文件**：企业微信官方文档写明，成员发给自建应用的消息只有文本、图片、语音、视频、位置、链接六种，没有文件（[接收消息与事件](https://developer.work.weixin.qq.com/document/path/90239)）。所以 Excel、Word、PDF 的主入口是菜单里的「上传资料」网页。代码也兼容客户端万一下发的文件消息，收到就按资料导入处理，但这不是官方保证的能力。

## 二、上线配置（管理员一次性）

1. 部署本版本。容器启动时会执行迁移 `c5d8e2f1a7b3`，新增 `sys_wecom_inbound` 表，给 `import_batch` 增加来源和压缩包名两列。
2. 企业微信后台 → 应用管理 → 聚成工作台 → **接收消息** → 设置 API 接收：
   - URL：`https://juchengcc.com/api/v1/wecom/callback`（和通讯录回调同一地址）
   - Token 与 EncodingAESKey：填工作台已配置的回调 Token 和 AESKey。如果此前只给通讯录配过回调、应用这里还没配，要用同一对值。
3. 工作台「系统管理 → 数据源」点 **下发菜单到企业微信**。之后同事在企业微信里重新进入应用，就能看到底部菜单。

如果下发菜单返回错误码，通常是 AgentID 不对，或者服务器出口 IP 没有加到应用的「企业可信 IP」。

## 三、智能上传

- **文档**：上传或导入时，大模型（当前为 DeepSeek）读文件名和正文前 3000 字，整理出规范标题、一两句摘要、2–5 个标签和分类。分类只能从现有分类树里选；模型给出不存在的分类时改用规则结果，给出不存在的二级分类时置空。页面会标「AI」，入库前由上传人确认。
- **表格**：用途描述、文件名、表头都认不出目标台账时，把表头和前 5 行发给大模型判断。判断是四类台账之一的，进入清洗预览；都不是的进待整理池，并写明「看起来是：车辆使用登记」，方便整理人处理。
- **zip 批量**：一个压缩包里的文件逐个分流，每个文件一条导入记录，记录上标明来自哪个压缩包。Windows 压缩的中文文件名（GBK）会自动还原。以下内容跳过并说明原因：嵌套压缩包、加密文件、单个超过 50MB 的文件、系统垃圾文件（`__MACOSX`、`.DS_Store`）。整包最多 100 个文件、解压后 200MB。
- **处理进度通知**：整理人替上传人导入台账、放进知识库、标记已处理或撤回时，上传人会收到站内通知和企业微信消息。多份资料同时进入待整理池时，整理人只收到一条合并通知。
- 只把正文开头、表头和样例行发给模型，不发整份文件。模型未配置、超时或返回不合法时，一律退回规则识别，上传不会因此失败。

## 四、验证

后端测试 324 项全部通过，其中本期新增 14 项（`tests/test_wecom_inbox.py`）：走真实加解密的回调全链路（文字问小聚和确认链接、搜知识库、帮助、重试去重、未开通成员、图片进待整理池、文件消息进知识库、素材过期、菜单点击与下发）、大模型识别（采纳、拒绝编造的分类、失败兜底）、zip（GBK 文件名、跳过规则、损坏/rar/超量拒绝），以及处理进度通知。迁移 `c5d8e2f1a7b3` 在空库上升级、降级、再升级都通过，与模型无差异。浏览器里在手机宽度验证了导入页卡片布局和 zip 上传结果，也看过系统管理里的菜单面板。

尚未在真实企业微信里验证：应用「接收消息」需要先在企业微信后台配置，之后要发一条文字和一张图片实测。

## 五、已知限制

- 小聚的回复靠服务进程里的后台线程等待。任务执行期间如果服务重启，这条回复会丢失，成员可在工作台的对话里查看结果。
- 图片暂不做文字识别，只归档进待整理池。
- 企业微信临时素材只保留 3 天，3 天内没处理完的图片消息无法再下载。
