# 资料导入与企业知识库（2026-10 第一期）

知识库从「乐享镜像」改为自建：原件存在公司服务器，工作台负责上传、分类、审核、检索。另新增全员可用的「资料导入」入口，让同事把格式不统一的资料直接交进来。

2026-10-30 修订：经理资料接入的操作说明与验证见 [经理资料接入](MANAGER_INTAKE.md)。部署时必须一起更新前后端（受保护原件下载现在需要本人登录态），实际运行版本以 `/health` 的 `revision` 为准。

## 一、资料导入（菜单：公共 → 资料导入，全员可见）

| 上传的文件 | 系统怎么处理 | 之后谁做什么 |
|---|---|---|
| 表格 xlsx / csv，能认出是合同 / 商机 / 回款 / 项目 | 先看用途描述和文件名，认不出再按表头匹配模板 | 有台账导入权限的人：点「核对并导入」进入数据清洗页确认映射后导入；没有权限：自动进待整理池 |
| 表格认不出是哪类台账（如用车登记） | 进待整理池 | 整理人决定导入台账、放进知识库，或标记已处理 |
| 文档 docx / pdf / pptx / md / txt | 抽取正文，模型建议标题/摘要/分类；模型不可用时使用规则并明确标识 | 上传人核对建议与可见范围，可批量提交；审核发布后才能检索 |
| 图片、扫描件 PDF（没有文字层） | 用公司已配置的多模态大模型逐页转录，正文标注「扫描识别」 | 上传人或整理人对照原件核对后再确认入库；单份超过 30 页先拆分 |
| 旧版 doc/xls/ppt、其他格式 | 进待整理池，写明原因 | 整理人处理；旧格式请先另存为新格式 |

- **整理人**：按钮权限 `imports:handle`，默认给营销管控专员（YX-01）和平台管理员。普通整理人只能处理进入待整理池或本人已接手的记录，且受 `self/dept/all` 范围约束；不能直接浏览别人尚未转交的原件。平台管理员可管理全部记录。动态角色配置同样参与通知与权限判断。
- **上传与识别分开**：网页先保存原件，再后台识别并刷新进度；离开页面不会取消后台识别。若服务中断，超过 5 分钟仍未完成可点「重新识别」，不重复上传原件。
- **扫描件与图片**：没有文字层的 PDF 页和图片交给多模态大模型逐页转录，不使用传统 OCR。模型沿用 `LLM_MODEL` 与 `LLM_API_KEY`（和小聚同一个网关），要单独换视觉模型时设置 `LLM_VISION_MODEL`；单份最多识别 30 页，超限明确拒绝而不是静默截断。识别正文缓存在 `import_batch.content`，确认入库时直接复用，不重复调用模型；点「重新识别」才会重读原件。原上传人、授权整理人和平台管理员可以查看识别全文，再决定是否入库。
- **进度**：识别中、待核对、待审核、已驳回、已发布、部分入库、未导入有效记录、已下架分别显示，不能把上传成功当作可供小聚使用。
- **多表 Excel**：先展示工作表列表、表头与样例，多工作表必须明确选择本次要导入的表；不会默默取一个表后声称全部导入。
- **撤回**：上传人或整理人可整份撤回。清洗预览直接取消；已导入台账的记录整批删除，但只要有一条已被后续业务使用（合同有回款或已归档、回款关联了银行流水、项目已有合同/成本/日记账/流程节点），就整体拒绝并列出原因；知识库文档未发布则删除、已发布则下架。
- **防重复**：同一人重复上传同一文件（按内容哈希）会被拦下；撤回后可以重新上传。不同经理同时预览后提交，系统会再次检查库内重复；若预览已经过期，要求刷新校验，不重复入账。
- 现有台账模板只有合同、商机、回款、项目四类。其他业务表（客户、应收、花名册等）要导入，需要先在 `clean_service.DEFAULT_TEMPLATES` 增加模板。

## 二、企业知识库（菜单：公共 → 知识库）

企微中的资料可通过「从企业微信导入」入口接入，支持链接、关键词搜索及本人绑定。具体读取范围、原始类型保留、授权与快照限制见 [企微资料接入](WECOM_IMPORT.md)。

**分类**：两级目录，首次访问自动写入默认分类树：

| 一级 | 二级 | 默认审核人 |
|---|---|---|
| 制度 | 人事制度 / 财务制度 / 行政制度 / 业务流程 | HR（RS-01）、总经办专员（ZB-02） |
| 售前 | 数字校园 / 综合智慧安防 / 素质教育考评 / 运维服务 | 售前（CP-01） |
| 方案模板 | 投标文件 / 实施方案 / 安装调试 / 验收资料 | 售前（CP-01） |
| 案例 | 数字校园 / 综合智慧安防 / 素质教育考评 | 售前、市场经理 |
| 资质 | 公司资质 / 人员证书 / 荣誉奖项 | 总经办专员、售前 |
| 产品 | 产品手册 / 技术参数 / 报价清单 | 售前 |
| 客服 | 排查手册 / 常见问题 / 运维规范 | 客服（KF-01） |
| 合同范本 | 销售合同 / 采购合同 / 保密协议 / 其他协议 | 营销管控、财务经理 |

- 一级内置分类被标书助手、客服排查建议、人事答疑按名称引用，不能改名或删除；二级分类和新增的一级分类可以随意维护（分类管理页，平台管理员或 `kb:manage`）。
- **审核**：分类审核人上传直接发布；其他人上传进入「待审核」，审核人收到站内/企微通知。驳回必须写原因；上传人修改后自动重新提交。
- **可见范围**：仅本人 / 全员 / 指定部门 / 指定角色。新资料默认本部门，无部门默认仅本人；不改变已有文档的共享范围。检索、文档数、分块数、原件和历史版本下载按权限复核。待审核资料可由分类审核人处理，知识库管理员具有管理权限；发布后普通阅读仍遵守所选范围。标书生成、客服建议等内部调用只用「已发布 + 全员可见」的文档。
- **原件隔离**：导入原件、知识库原件、清洗源文件及清洗报告要求登录并重新检查权限，仅凭文件编号或复制签名链接不能跨账号下载。知识文档缩小可见范围后，旧链接及历史版本也遵守当前权限。
- **代办归属**：整理人代为提交知识库时保留原上传人和默认部门，原上传人能看到进度、审核结果并按业务约束撤回。
- **版本**：同一文档再传会生成 v2、v3…，历史版本原件都可下载。已发布文档只能下架，不能删除。
- 支持格式：docx、pdf（文字层或扫描版）、pptx、xlsx、md、txt，以及 png/jpg/bmp/tif/webp 图片；单个 ≤ 50MB。扫描件和图片按页调用多模态模型，单份最多 30 页（`LLM_VISION_MAX_PAGES`）。

## 四、备份与恢复

`backup` 服务每天 02:30 在服务器 `/opt/jucheng/deploy/backups/` 生成：

- `jucheng_YYYY-MM-DD.dump`：数据库（`pg_dump -Fc`）
- `files_YYYY-MM-DD.tar.gz`：上传文件卷（知识库原件、导入资料、合同归档、报表）

各保留 7 天。两者要成对恢复，否则数据库里的文件记录会找不到原件：

```bash
cd /opt/jucheng/deploy && docker compose stop api
cd /opt/jucheng/deploy && docker compose exec -T db pg_restore -U jucheng -d jucheng --clean --if-exists < backups/jucheng_2026-10-24.dump
cd /opt/jucheng/deploy && docker compose run --rm -v "$PWD/backups:/backups" --entrypoint sh api -c 'rm -rf /data/files && tar -xzf /backups/files_2026-10-24.tar.gz -C /data'
cd /opt/jucheng/deploy && docker compose start api
```

**备份目前只在同一台服务器上**，服务器或磁盘损坏时会一起丢失。建议把 `backups/` 每天同步到腾讯云 COS 或另一台机器（例如 `coscmd` / `rclone` 定时任务），这一步需要你们提供存储桶和密钥后再配置。

## 五、已知限制（第二期）

- 扫描件和图片由多模态模型逐页转录，不是传统 OCR：可能识别错字、漏行或混淆相似数字，必须由人对照原件核对金额、编号、日期和签章页；单份最多 30 页，超限请拆分。
- 扫描页会整页发送到公司配置的大模型网关；未单独配置时沿用 `LLM_MODEL` 和同一个 `LLM_API_KEY`，图片不落外部存储，只保留识别出的正文。
- 表格只能导入四类台账；其他表格只能作为知识库资料或由整理人线下处理。
- 列映射由规则识别，暂未接入大模型辅助；格式特别乱的表格需要人工在清洗页调整映射。
- 撤回已导入的合同不会恢复项目上被顺带填写的合同金额/状态。
- 表格导入最多 20MB、每表 20000 行/200 列/100 万单元格；知识文档最多 50MB，表格转知识正文最多 20000 条非空行；超限明确拒绝，不静默截断后宣称成功。
- 后台识别使用应用进程任务，不是持久化队列。原件与识别中状态持久化；服务中断后的识别由用户重试，不自动重放业务写入。
