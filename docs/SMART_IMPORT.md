# 小聚智能导入

## 使用

上传文件或 ZIP 后，小聚在后台读取内容。整理完成会自动弹出清单，说明：

- 资料是什么、准备进入哪些位置、判断依据是什么。
- 将新增多少记录，哪些重复或异常内容会跳过。
- 合同、金额、日期、客户、业务线与分期应收等具体数据。
- 对台账、经营看板、业绩统计和知识检索的影响。

点击「是，按清单导入」后执行；点击「否，不导入」保留原件，不写入业务数据。缺少台账导入权限时，点击是会交给授权整理人确认，不扩大上传人的权限。其他待确认资料可以从「让小聚整理」进入同一流程。

支持多份文件、多个工作表、文档和扫描件中的结构化业务内容。真实合同原件归到「业务资料 / 合同原件」，与可复用合同范本分开；采购清单、进度表等也有相应资料分类。

## 额度

| 项目 | 限额 |
|---|---|
| ZIP 压缩包 | 512MB |
| 每包文件数 | 500 |
| 解压后总体积 | 2GB |
| 每个内部文件 / 单独上传文件 | 50MB |
| 表格 | 每表 20000 行、200 列、100 万单元格 |
| 扫描识别 | 每份最多 30 页（沿用现有配置） |

网页从 `/api/v1/imports/limits` 读取限额。ZIP 使用 FastAPI 已落到临时磁盘的上传流，预先校验目录，再逐份解压，不把 2GB 解压内容同时堆到内存。Nginx 请求上限为 520MB，预留 multipart 开销。加密文件、嵌套压缩包、超大条目会明确列出原因；整个包超限时拒绝，不静默截断。

## 数据关系

- 合同、商机、项目、实际回款使用原清洗校验、编码、去重与业务模型。文档提取的金额、客户、编号和日期要有原文依据。
- 同份资料的项目与合同，在客户和业务线一致、匹配项目唯一时按预览自动关联；项目编码在确认后生成。
- 合同付款条件进入应收计划，保留原文条件；比例可按合同总额计算金额。没有明确日期的条款不编造日期。应收计划不计作已到账。
- 原件关联到合同详情；回款计划状态使用现有业务逻辑。合同日期决定对应期间，历史合同不算成本月新签。
- 其他已有模块可准备受权限约束的客服、项目进展、日记账、考勤、流水或财务文件登记请求，由同一确认单提交。
- 对应业务模型不存在的采购/库存等明细，进入业务资料归档，并在清单明确呈现实际去向；归档不等于已记成本或已付款。
- 已发布文档才进入知识检索。非分类审核人提交的文档沿用审核规则，弹窗会事先说明。
- 成功写入后清除经营看板缓存，打开的工作台、看板、业绩和利润页面接收刷新信号；新生成报表读取同一业务数据。已生成的报表文件保留生成时快照。

## 重复与失败

同一人上传相同内容，即使改了文件名，也会弹出重复提醒。压缩包内重复文件单独列出；全部重复时不会新建导入批次。业务行在准备阶段和提交阶段都查重，同文件跨表的重复也会列出，确认时已有的重复记录会跳过。

清单有版本号，过期清单需刷新。重复点确认不会重复执行。每个台账步骤的写入与回执在同一数据库事务中提交；其他模块复用小聚的持久化幂等回执。中断后保留已完成记录，只继续尚未完成步骤。重启不会替用户批准清单。

撤回按原业务引用约束执行：已经产生实际回款、后续成本或流程引用的记录不能直接删除；跨模块业务从实际回执进入对应模块处理。

## 实现

- `intake_agent.py` 负责分析草案、确认、执行、回执和恢复；草案存在 `ImportBatch.suggestion`，无需改表。
- `pi_bridge.py` 调用现有 `backend/agent_runtime/run.mjs`，使用小聚同一 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL`，没有新增独立密钥。
- Pi 的资料配置只暴露读取、查询和准备草案的工具，没有主机命令、工作区写入、MCP 或业务提交工具。辅助查询达到限额后移除查询工具，生成确认单后即停止等待人决定。
- 网页上传传 `intelligent=true`；企业微信网页导入同样启用。旧 API 调用可继续使用原兼容流程。小聚业务目录包含整理与决定能力，审批仍由人的具体确认触发。

- 实测文件均为合成验收资料。线上旧资料只重新整理为待确认清单，未代替人批准实际业务写入。
