# 本地管理员与真实企业账号关联

账号关联仅适用于所有者明确核实后的本地 `admin` 与当前公司已建档企业 UserID。名称相同、企业微信超级管理员身份或扫码登录本身都不会自动触发关联。其他账号及其权限、资料、个人企微连接保持独立。

迁移后，企业账号成为统一身份，继承原 `admin` 的完整工作台角色；输入 `admin` 和原有安全密码仍可登录，旧的有效网页登录和 MCP 接入归到同一身份。原 `admin` 数据库 ID 归档保留，审计日志和历史财务确认人的 ID 不被改写。后续业务由真实企业账号登记，避免两个账号继续产生分散数据。

## 迁移内容

- 项目及合同负责人、运营项目所有者、导入与清洗记录、附件、知识资料、标书产物、个人报表和通知的归属迁到目标账号。
- 小聚历史对话、工作文件、任务结果和回执保留，重新绑定经过核实的所有者及当前权限范围。未完成的执行单取消，不能沿用旧确认自动执行。
- 原有 WorkBuddy 令牌保持可用，保存的个人配置按新账号重新加密；目标已有独立密码或不同 MCP 令牌时停止自动覆盖。
- 原管理员的个人企微凭证不复制。目标使用自己扫码授权的个人连接，按企微实际授权范围处理业务。
- 历史消息不自动补发。原管理员停止作为独立业务账号参与定时同步，登录名仍作为显式别名保留。
- 历史金融金额、回款、成本和审计原件不重新登记，不重复记账。

## 受控操作

先核对目标 CorpID、企业 UserID 和成员身份，备份数据库、小聚目录及原账号工作目录。命令默认只读预览，不对公网开放通用合并接口。

```bash
cd backend
.venv/bin/python -m scripts.link_admin_account --source-id <旧管理员ID> --target-id <企业账号ID> --expected-userid <已核实UserID> --operator-id <操作人ID>

# 核对预览后执行；backup-dir 必须是未存在的私有目录
.venv/bin/python -m scripts.link_admin_account --source-id <旧管理员ID> --target-id <企业账号ID> --expected-userid <已核实UserID> --operator-id <操作人ID> --backup-dir /data/account-link-backups/<独立批次> --apply
```

数据库修改在同一事务内提交。文件修改先保存私有备份，发生异常时恢复；同 ID 的目标会话、工作文件或企微来源记录冲突时停止覆盖。相同关联重跑返回已完成，不重新迁移或重复建立资料。

`sys_user.preferences.verified_account_link` 保存经过核准的源、目标与企业绑定。登录解析严格核对本地 `admin`、双方管理角色、当前企业和目标企业 UserID；关联失效、目标停用或出现链式关联时拒绝登录。该字段不能通过普通个人偏好接口写入。

## 验证

`tests/test_account_link.py` 使用独立数据库事务和临时文件，验证原登录名、旧会话、MCP、资料归属、对话、历史确认取消、文件异常回滚、错误目标拒绝、演示密码阻止和其他账号保持独立。

企微连接通过官方 CLI 扫码并保存于目标账号自己的凭证目录。目录中有某个服务或方法，只代表已接入调用入口；每次调用仍由企微校验功能授权和具体资源访问权。不会因工作台管理员角色而获得其他成员的个人空间。
