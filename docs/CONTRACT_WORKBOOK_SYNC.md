# 已签合同台账 · 企业微信同步

在聚成工作台打开「合同台账 → 企业微信同步」，可以查看最近检查和更新的时间、所有子表、业务记录及待核对行。切换「逐格查看」可以查看源表列；点击「明细」可以看单元格的原值、公式、附件链接、候选业务记录以及回款差额。合同和商机详情可回到对应的源表行。工作台快照为当时数据的 XLSX 副本，保留结果值和合并区；查看原始样式和活动公式请打开企微原表。

| 子表 | 业务去向 |
| --- | --- |
| 2026 年销售合同、2026 年前、长效合同、已签已回款 | 合同主档及累计回款对账 |
| 待签合同、招标状态项目、市场商机 | 商机主档；招标标段等附属行在原表保留 |
| 与中移项目 | 有对应记录的合同主档；小计、补贴和海洋项目等其他分区保留为源表明细 |

同步每 10 分钟检查企微版本，未变化就跳过。首次把原表行和已有记录按业务字段、明确编号或有字段佐证的历史来源关联；以后按稳定来源身份跟踪修改和移行。增加「合同编号」或「同步编号」列后可用其唯一值关联，同时改动名称、客户等字段时尤其有用。源表移除行会显示状态并保留已有台账，重名或信息不全的行仍能查看。业务表头变化、源表缺少日期或出现不唯一的身份时，对应行需要核对。项目只有在名称及客户唯一一致时才补关联。

绑定账号可以在「未对应 → 明细」输入已核实的合同或商机编号，保存对应关系。关联前会校验源表版本和是否已关联其他行。信息未齐全且没有已有业务记录的行，可补正企微原表后再同步。

原表累计回款和到账台账分开展示，差额从当前合同的回款记录实时核对。开启「明确到账同步」后，原表给出完整日期和金额、逐笔合计与累计已收一致且与既有回款无冲突的记录，经统一收款服务进入到账台账；可以唯一对应旧回款时只补来源，无新增合同回款。只有累计金额或最后到账日、缺少完整明细的部分仍待核对。来源编号用于防重，不冒充银行回单；原表未填写的付款方和账户保留为「原表未注明」。合同计划、银行流水、核销与归档原件仍由各自的业务流程维护。

工作簿详情、导出和明细回链只对绑定人以及配置的工作台部门/账号可见；合同、商机原有权限照常生效。绑定使用工作台本人的官方企微连接，记录绑定版本；如果企微收回权限或机器人授权到期，同步会暂停更新、保留最近完整数据并显示失败原因。绑定人可在工作台的同步状态里直接打开企业微信官方授权入口，完成后点“授权完成，重新检查”即可回读；恢复后入口仍保留，便于下一次续期。授权链接只对固定来源绑定人展示，并且只接受企业微信官方 HTTPS 域名。如果更换绑定，需要重新保存固定来源。企业微信来源没有被修改。

运维命令在 API 容器内运行：

```bash
python -m scripts.contract_workbook bind <来源标识> --title <名称> --url <企微在线表格链接> --reader-id <工作台账号ID> --department <可见部门ID> --auto-apply --auto-receipts --paused
python -m scripts.contract_workbook preview <来源标识>
python -m scripts.contract_workbook run <来源标识> --force
python -m scripts.contract_workbook resume <来源标识>
python -m scripts.contract_workbook status <来源标识>
```

可用 `--profile <子表ID>=<映射>` 固定业务映射，避免子表改名影响识别。新子表仍保存原始数据，映射需核实后再配置。微盘真实 XLSX 的绑定地址写作 `wedrive:<文件ID>`，下载后按文件内容计算版本。当前这份表使用企微在线表格读取；它的 Excel 导出副本不作为自动同步来源。

接口依据：[企业微信官方 CLI](https://github.com/WecomTeam/wecom-cli)、[在线表格读取能力](https://github.com/WecomTeam/wecom-cli/blob/main/skills/wecomcli-sheet/SKILL.md)。验收见 `backend/tests/test_contract_workbook.py`。
