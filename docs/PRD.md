# 1. 项目概述

## 1.1 背景

聚成数智当前经营数据分散在多个系统中：企业微信审批、银行流水、柠檬云账套、Excel 台账等。由此产生：

- 人工汇总耗时、口径不统一、决策缺乏实时依据；
- 报销与项目归集脱节、出纳日记账手工逐笔登记；
- 周报月报人工催收与汇总；
- 经营数据无法实时查看；客户咨询、招投标文档处理依赖人工。

本项目的核心思路是 **「统一工作台 + 统一入口」**：自建一套轻量级企业工作台承载所有业务集成与数据归集，并通过标准 **MCP Server** 将工作台能力暴露给腾讯 WorkBuddy，使 WorkBuddy 成为全员唯一的 AI 办公入口——「说一句话完成报销查询、合同登记、周报生成、方案撰写」。

## 1.2 产品定位

| 维度   | 定位                                                             |
| ---- | -------------------------------------------------------------- |
| 用户规模 | 全公司约百人规模                                                       |
| 终端形态 | PC 浏览器（HTTPS）为主；WorkBuddy 桌面端（Windows/Mac）作为 AI 入口；企业微信侧边栏接收推送 |
| 系统形态 | B/S 架构自研 Web 工作台 + MCP Server 网关，部署于腾讯云                        |
| 数据主权 | 业务数据统一落库腾讯云 MySQL；文件归档 COS；WorkBuddy 侧不落地业务数据                  |

## 1.3 项目目标

1. **数据一次录入、全程自动流转**：企微审批通过 → 台账自动登记 → 报表/看板自动更新。
2. **报表一键更新替代月末手工整理**：每日支出报表、每周项目利润表、公司周报/月报自动生成。
3. **经营看板每天一页看全公司**：回款/合同/商机/项目/提交率五大板块实时可视，每日企微晨报推送。
4. **WorkBuddy 对话即办**：MCP Server 首批 9 个 Tool 上线，覆盖财务、OA、CRM、看板、知识库、人事、项目七类能力。
5. **写作与合规检查覆盖八个部门高频场景**（周报、晨报、方案、标书合规、考勤分析等）。

## 1.4 非目标（本期不做）

- 不替换企业微信审批流、柠檬云账务系统——本平台只做**集成、归集、分析与呈现**。
- 不做原生 App / 微信小程序。
- 不做多租户 SaaS 化。
- 客服「常见问题自动应答」仅到二期（本期到「辅助排查 + 归因分析」）。
- 财务核算凭证仍以柠檬云为准，本平台不做账务复式记账。

## 1.5 名词术语

| 术语           | 说明                                                                 |
| ------------ | ------------------------------------------------------------------ |
| 工作台 / Portal | 本项目自研的统一 Web 工作台                                                   |
| MCP          | Model Context Protocol，WorkBuddy 与工作台间的工具调用协议，传输方式 Streamable HTTP |
| Tool         | MCP Server 对外暴露的一个可调用工具（如 fin.daily_expense_report）                |
| P0 / P1      | P0 = 最优先落地（财务/总办/市场）；P1 = 同步开发、滚动上线                                |

| 归集           | 将费用/收入按项目维度关联聚合的过程                                                 |
| 晨报           | 每日 08:00 通过企微应用消息推送的经营摘要（含看板链接）                                    |
| 数据口径         | 指标统计规则（如「当月回款」的定义），见第 3 章                                          |

# 2. 总体架构

## 2.1 五层逻辑架构

```
┌─────────────────────────── 终端接入层 ACCESS ───────────────────────────┐
│  WorkBuddy 桌面端(Windows/Mac)   浏览器(HTTPS 工作台)   企微侧边栏(推送)  │
└──────────────────────────────────┬──────────────────────────────────────┘
                                   │ 对话 / 点击 / 推送
┌──────────────────────────────────▼──────────────────────────────────────┐
│                    AI 入口层：WorkBuddy（腾讯）+ 内置 MCP Client           │
└──────────────────────────────────┬──────────────────────────────────────┘
                                   │ MCP 协议（Streamable HTTP + Access Token）
┌──────────────────────────────────▼──────────────────────────────────────┐
│                统一工作台应用层 PORTAL（自建 · 腾讯云部署）                 │
│  个性化门户 │ 经营看板 │ 报表中心 │ 台账中心 │ 知识库 │ MCP Server 网关      │
│  认证鉴权(RBAC) │ 定时任务引擎 │ 消息通知 │ 文件服务(COS)                   │
└──────────────────────────────────┬──────────────────────────────────────┘
                                   │ REST API / 适配器接口
┌──────────────────────────────────▼──────────────────────────────────────┐
│                             数据集成层 INTEGRATION                        │
│  企微开放平台 │ 柠檬云财务 │ 银行流水文件 │ 税务申报文件 │ 合同/商机台账       │
└──────────────────────────────────┬──────────────────────────────────────┘
                                   │ 结构化落库 MySQL + 文件归档 COS
┌──────────────────────────────────▼──────────────────────────────────────┐
│        云基础设施层：CVM(4核8G) │ 云数据库MySQL │ Redis │ COS │ 域名+SSL    │
└─────────────────────────────────────────────────────────────────────────┘
```

**关键机制**：工作台是中枢——向下通过适配器集成业务系统，向上通过 MCP Server 服务 WorkBuddy。新增场景只需在工作台注册新 Tool，WorkBuddy 侧无需升级。

## 2.2 技术选型（定稿，严格按方案执行）

| 层       | 选型                                                   | 说明                                              |
| ------- | ---------------------------------------------------- | ----------------------------------------------- |
| 前端      | Vue 3 + Element Plus + ECharts                       | 响应式布局，适配 PC 浏览器与企微内嵌页                           |
| 后端      | Python 3.12+ FastAPI + Celery                        | 与 WorkBuddy 生态一致，便于 MCP SDK 接入；Celery 承载定时与异步任务 |
| 数据库     | 腾讯云 MySQL 8.0（业务主库）                                  | 每日自动备份，7 天保留                                    |
| 缓存/队列   | Redis（1G 标准版）                                        | 会话缓存、企微 access_token 缓存、Celery Broker           |
| 对象存储    | 腾讯云 COS                                              | 合同原件、标书、生成的报表/方案归档，开启版本控制与私有读写                  |
| 认证      | 企业微信 OAuth2 扫码/网页授权登录                                | 免密统一身份，通讯录自动同步；开发期提供 Mock 登录                    |
| MCP SDK | Python 官方 MCP SDK（FastMCP）                           | Streamable HTTP 传输                              |
| ORM/迁移  | SQLAlchemy 2.x + Alembic                             | 数据库迁移版本化                                        |
| 部署      | Docker Compose（Nginx + FastAPI + Celery Worker/Beat） | 单机起步，二期可扩展 CLB + 双机                             |

## 2.3 部署拓扑

- 1 台 CVM（标准型 S6 4核8G，系统盘 60G SSD + 数据盘 100G）承载全部容器；
- 云数据库 MySQL（基础型 2核4G，100G 高性能云盘）走内网访问，不开公网；
- Nginx 443 对外，安全组仅放行 80/443；Let's Encrypt 或腾讯云 DV SSL，强制 HTTPS；
- 域名：`portal.jc-digital.cn`（或客户最终注册域名），ICP 备案通过后绑定；
- 企微回调 URL 与 MCP Server 地址均走该域名。

# 3. 数据口径与编码规则（建议稿 · 待财务评审）

> ⚠️ 本章为开发组建议稿，标注「待财务评审」。开发可先行按本稿实现，口径字段全部走 `sys_dict` 字典配置化，评审变更只改配置不改代码。

## 3.1 项目编码规则

- 格式：`JC-<业务线码>-<年份>-<三位流水号>`，如 `JC-ZY-2026-001`。
- 业务线码：`ZY` 智慧园区、`XT` 系统集成、`YW` 运维服务、`RJ` 软件交付。
- 流水号按业务线当年内递增，由系统生成、人工不可改。
- 合同、报销、回款、商机均通过 `project_code` 关联项目；项目建档后编码终身不变。

## 3.2 部门与角色编码

部门编码见 1.6（ZB/CW/SC/YX/CP/RS/XM/KF/ADMIN）。角色编码：`dept-code` + 角色序号，如 `CW-01` 财务经理。与企微部门 ID 的映射存于 `sys_department.wecom_dept_id`。

## 3.3 费用归集规则（核心口径，待财务评审）

1. **报销归集**：企微报销审批模板增加必填字段「所属项目」（选项为系统项目列表）。审批通过后按该字段归集到项目；模板字段 key 约定 `project_code`（自定义控件）。
2. **无法归集的费用**：计入「公共费用」，报表中单列为「管理费用-公共」，不摊入项目毛利（是否按比例分摊待财务评审后配置）。
3. **银行流水归集**：流水解析入库后由出纳标记关联报销单/合同回款；未关联流水进入「待核对池」。
4. **项目成本构成**：归集报销费用 + 柠檬云项目辅助核算数据（API 可用时）+ 人工标记的采购成本。
5. **项目毛利** = 项目收入（合同额 / 确认收入，口径待评审）− 归集成本费用。

## 3.4 业绩与回款口径（待财务评审）

| 指标      | 建议口径                                |
| ------- | ----------------------------------- |
| 当月合同签订额 | 签订日期（企微合同审批通过日）落在本月的合同金额合计          |
| 当月回款    | 回款登记日期在本月的回款金额合计（以银行流水到账日为准）        |
| 年度累计业绩  | 当年签订合同金额合计                          |
| 回款目标达成率 | 当月回款 ÷ 当月回款目标（目标按业务线配置于 `sys_dict`） |
| 商机漏斗阶段  | 线索 → 初步接触 → 方案报价 → 商务谈判 → 赢单/丢单     |

## 3.5 报表口径

- **每日支出报表**：统计昨日 00:00–24:00 审批通过的报销 + 已核对流水支出，按部门/项目两个维度输出；每日 08:00 生成并推送。
- **每周项目利润表**：统计周期为自然周（周一至周日），每周一 09:00 生成上周报表。
- **公司周报/月报**：整合柠檬云凭证汇总、银行流水、税务申报数据、周报月报提交率，口径统一后由报表引擎合成。
- **月报提交率**：以企微「汇报」API 读取的提交记录为准，按部门统计。

# 4. 数据库设计

> 命名规范：系统表前缀 `sys_`，业务表 `biz_`，财务表 `fin_`，报表快照 `rpt_`，集成同步 `sync_`，审计 `log_`。所有表含 `id BIGINT PK AUTO_INCREMENT`、`created_at`、`updated_at`，逻辑删除 `is_deleted`（除审计表）。字符集 utf8mb4。

## 4.1 ER 概览（核心关系）

```
sys_user ──< sys_user_role >── sys_role
sys_user ──< biz_project(负责人)          biz_contract ──< biz_payment
sys_department ──< sys_user               biz_contract.project_code ──┐
biz_project ──< biz_project_milestone                                 │
biz_expense_report.project_code ──────────────────────────────────────┘
biz_expense_report ──< biz_expense_item
fin_bank_flow ──> fin_cash_journal(核对生成)
sync_wecom_approval ──> biz_contract / biz_expense_report / biz_opportunity(事件分发)
rpt_daily_expense / rpt_project_profit / rpt_company_period（快照表）
mcp_tool ──< log_mcp_audit
```

## 4.2 表结构明细

### 4.2.1 系统与权限

**sys_user（用户）**

| 字段             | 类型              | 说明                |
| -------------- | --------------- | ----------------- |
| wecom_userid   | varchar(64) UK  | 企微 userid，唯一      |
| name           | varchar(64)     | 姓名                |
| department_id  | bigint FK       | 主部门               |
| email / mobile | varchar         | 联系方式              |
| status         | tinyint         | 1 在职 2 离职         |
| access_token   | varchar(128) UK | MCP 访问令牌（与企微账号绑定） |
| last_login_at  | datetime        | —                 |

**sys_department**：`dept_code varchar(8) UK`、`name`、`wecom_dept_id bigint`、`parent_id`。

**sys_role**：`role_code varchar(16) UK`、`name`、`dept_code`、`permissions json`（菜单/按钮/数据范围）。  
**sys_user_role**：`user_id`、`role_id`。


**sys_dict（字典/口径配置）**：`dict_type`（如 `payment_target` 回款目标、`business_line`、`opportunity_stage`）、`dict_key`、`dict_value json`、`remark`、`status`。

### 4.2.2 项目域

**biz_project（项目）**

| 字段                 | 类型             | 说明                         |
| ------------------ | -------------- | -------------------------- |
| project_code       | varchar(32) UK | JC-ZY-2026-001             |
| name               | varchar(128)   | 项目名称                       |
| business_line      | varchar(8)     | ZY/XT/YW/RJ                |
| customer_name      | varchar(128)   | 客户                         |
| owner_id           | bigint FK      | 项目经理                       |
| status             | tinyint        | 1 招标中 2 在建 3 已验收 4 运维 5 结项 |
| contract_amount    | decimal(14,2)  | 合同额（可空，由台账汇总）              |
| milestone_template | varchar(32)    | 流程模板标识                     |
| remark             | text           | —                          |

**biz_project_milestone（项目流程节点）**：`project_id FK`、`node_name`（深化设计/进度/采购/到货验收/终验…）、`seq int`、`owner_id`（节点责任人）、`plan_date`、`finish_date`、`status`（1 未开始 2 进行中 3 已完成 4 延期）、`alert_flag`（延期自动标红）。

### 4.2.3 合同与商机域

**biz_contract（合同台账）**

| 字段                 | 类型              | 说明                  |
| ------------------ | --------------- | ------------------- |
| contract_no        | varchar(32) UK  | HT-2026-0012（可系统生成） |
| project_code       | varchar(32) IDX | 关联项目                |
| customer_name      | varchar(128)    | 客户                  |
| amount             | decimal(14,2)   | 合同金额                |
| sign_date          | date            | 签订日期（=企微审批通过日）      |
| business_line      | varchar(8)      | 冗余，便于统计             |
| source_approval_no | varchar(64)     | 来源企微审批单号（可追溯）       |
| source_type        | tinyint         | 1 企微审批自动登记 2 人工录入   |
| status             | tinyint         | 1 履行中 2 已归档 3 已终止   |
| archive_file_url   | varchar(255)    | COS 归档地址            |

**biz_payment（回款）**：`contract_id FK`、`amount`、`payment_date`（=流水到账日）、`bank_flow_id`（关联流水，可空）、`register_by`、`source_type`（1 流水核对生成 2 人工）。

**biz_opportunity（商机信息表）**：`opp_no UK`、`name`、`customer_name`、`stage`（漏斗阶段）、`amount decimal`、`expected_sign_date`、`owner_id`、`source_approval_no`（商机工单审批号）、`status`（赢单/丢单/进行中）。

### 4.2.4 财务域

**biz_expense_report（报销单归集）**

| 字段           | 类型              | 说明                      |
| ------------ | --------------- | ----------------------- |
| approval_no  | varchar(64) UK  | 企微审批单号                  |
| applicant_id | bigint FK       | 申请人                     |
| project_code | varchar(32) IDX | 归属项目（空=公共费用）            |
| amount       | decimal(12,2)   | 报销总额                    |
| expense_date | date            | 费用发生日                   |
| category     | varchar(32)     | 费用类别（差旅/采购/招待…）         |
| status       | tinyint         | 1 审批中 2 已通过 3 已驳回 4 已归集 |
| detail json  | —               | 企微审批模板字段快照              |

**biz_expense_item（报销明细）**：`report_id FK`、`item_name`、`amount`、`invoice_count`。

**fin_bank_flow（银行流水）**：`bank_account`、`trade_date`、`direction`（1 收 2 支）、`amount`、`counterparty`、`summary`、`balance`、`source_file`（来源文件名）、`match_status`（0 未核对 1 已关联报销 2 已关联回款 3 公户支出）、`biz_ref`（关联单号）。

**fin_cash_journal（出纳日记账）**：`journal_date`、`account_type`（现金/银行）、`direction`、`amount`、`summary`、`bank_flow_id`（由流水核对生成）、`register_by`、`source_type`（1 流水自动 2 手工）。

**fin_voucher（柠檬云凭证摘要）**：`voucher_no`、`voucher_date`、`summary`、`amount`、`direction`、`subject_code`、`subject_name`、`aux_project`（项目辅助核算）、`sync_batch`。

**fin_subject_balance（科目余额）**：`period`（如 2026-10）、`subject_code`、`subject_name`、`debit_balance`、`credit_balance`。

**sync_tax_filing（税务申报归集）**：`period`、`tax_type`（增值税/所得税等）、`payable_amount`、`file_url`（COS 申报表原件）。

### 4.2.5 汇报与通知域

**oa_submission（日报/周报/月报提交记录）**：`user_id FK`、`report_type`（daily/weekly/monthly）、`period`（如 2026-W42）、`submit_time`、`wecom_report_id`、`stat_status`。

**sys_notify（消息通知）**：`user_id`、`channel`（wecom_app/inapp）、`msg_type`（morning_report/approval/overdue/alert）、`title`、`content`、`ref_type/ref_id`、`sent_at`、`read_status`。

### 4.2.6 知识库与客服域

**kb_document**：`title`、`category`（制度/售前/方案模板/案例/资质）、`file_url`（COS）、`content_text`（抽取的全文）、`version`、`uploader_id`。  
**kb_chunk（检索分块）**：`doc_id FK`、`chunk_text`、`seq`、`embedding`（预留向量字段，本期用关键词+全文检索即可）。

**cs_ticket（客服问题）**：`ticket_no UK`、`customer_name`、`channel`（电话/微信/邮件）、`problem_desc`、`category`（自动分类）、`dedupe_hash`（去重指纹）、`related_ticket_ids json`、`root_cause`、`solution`、`handler_id`、`status`（1 登记 2 排查中 3 已解决 4 已归因）。

### 4.2.7 人事域

**hr_attendance_record（考勤明细）**：`user_id`、`work_date`、`check_in`、`check_out`、`exception_type`（迟到/早退/缺卡/请假/加班）、`source_file`。  
**hr_attendance_summary（月度汇总）**：`user_id`、`period`、`late_times`、`absent_times`、`overtime_hours`、`leave_days`、`report_url`（汇总表文件）。  
**hr_contract_alert（合同/试用期到期预警）**：`user_id`、`contract_end_date`、`probation_end_date`、`alert_sent`。

### 4.2.8 集成与审计域

**sync_wecom_approval（企微审批事件）**：`sp_no UK`（审批单号）、`template_key`（contract/expense/opportunity…）、`applicant_id`、`status`（1 审批中 2 通过 3 驳回 4 撤销）、`apply_time`、`detail json`、`dispatch_status`（0 未处理 1 已分发 2 失败）。

**mcp_tool（工具注册表）**：`tool_code UK`（fin.daily_expense_report）、`name`、`description`、`allowed_roles json`、`enabled`。  
**log_mcp_audit（MCP 审计）**：`user_id`、`tool_code`、`params json`（脱敏）、`result_summary`、`cost_ms`、`client_ip`、`called_at`。

**sync_job_log（定时任务日志）**：`job_name`、`run_at`、`status`、`rows_affected`、`error_msg`。

### 4.2.9 报表快照

**rpt_daily_expense**：`stat_date`、`dimension`（dept/project）、`dim_value`、`total_amount`、`expense_count`、`detail json`。  
**rpt_project_profit**：`week_no`、`project_code`、`income`、`cost`、`gross_profit`、`gross_margin`。  
**rpt_company_period**：`period`、`type`（weekly/monthly）、`metrics json`（回款/签约/商机/提交率等聚合）、`file_url`。

# 5. 功能需求（工作台核心）

> 需求编号规则：FR-模块-序号。每条需求含：描述、优先级、验收标准。

## 5.1 FR-01 统一认证与账号体系（P0）

### 描述

企业微信 OAuth2 免密登录 + 通讯录自动同步 + 部门×角色 RBAC。开发期提供 Mock 账号登录（见第 8 章）。

### 功能点

| 编号       | 需求                                                                         | 优先级 |
| -------- | -------------------------------------------------------------------------- | --- |
| FR-01-01 | 企微 OAuth2 网页授权登录：跳转企微授权 → code 换 userid → 签发会话 JWT（2h 有效，滑动续期）             | P0  |
| FR-01-02 | 通讯录同步：定时（每日 06:00）+ 手动触发，全量拉取部门与成员，增量更新 sys_user / sys_department；离职成员自动禁用 | P0  |
| FR-01-03 | RBAC：菜单权限、按钮权限、数据范围（本人/本部门/全公司）三级控制                                        | P0  |
| FR-01-04 | Mock 登录：开发/演示环境用「选择身份」页直接登录，仅 `DATA_SOURCE_MODE=mock` 时开启                  | P0  |
| FR-01-05 | MCP Access Token：为每个用户生成个人 Token（与企微账号绑定），支持重置                             | P0  |
| FR-01-06 | 首次登录自动初始化默认角色（按部门映射）                                                       | P1  |

### 验收标准

- 企微内打开工作台免密进入；浏览器扫码登录可用（P1，依赖企微扫码配置）；
- 权限矩阵测试：财务仅可见财务与公共菜单；普通员工看不到台账中心；
- 数据范围：项目经理只能看到自己负责的项目。

## 7.1 财务部（P0）

**核心命题**：打通「费用报销 → 项目归集 → 报表生成」全流程。

**痛点**：出纳日记账手工逐笔登记；报销归集口径模糊、项目核算靠事后拆分；缺少按项目维度的收入/成本/毛利报表；月度报表与财务分析靠月末手工整理。

**方案落点**

| 场景                | 实现                         | 关联需求           |
| ----------------- | -------------------------- | -------------- |
| 报销发生时即确定项目归属      | 企微报销模板新增「所属项目」必填项，审批通过自动归集 | FR-05-04 / 6.1 |
| 每日支出自动生成报表        | 定时归集当日报销+流水，晨间推送财务与总办      | FR-04-01       |
| 银行流水半自动登记         | 流水文件解析比对更新出纳日记账            | FR-09-02/03    |
| 每周自动生成项目利润表       | 项目收入 − 归集成本费用              | FR-04-02       |
| 公司周报/月报自动汇总       | 整合柠檬云、税务申报数据一键生成           | FR-04-03/04    |
| 合同归档后自动读取回款更新项目报表 | 归档触发回款关联任务，每周刷新在建项目运营报表    | FR-05-06       |

**用户故事**

- 作为出纳，我上传网银流水文件后，系统自动解析入库并给出核对建议，我确认后日记账自动登记——替代逐笔手录。
- 作为财务经理，我每天早上在工作台和企微同时收到昨日支出报表，无需手工汇总。
- 作为财务经理，我在 WorkBuddy 里说「生成本周各项目利润表」，直接收到带毛利的报表文件。
- 作为会计，我查看任一项目可以看到：合同收入、已归集费用、当前毛利，口径统一。

**数据来源**：银行流水（现金/银行日记账）、企微审批与报销数据、柠檬云凭证/科目余额（P1）、税务申报数据（P1）。

| 场景      | 实现                                      |
| ------- | --------------------------------------- |
| 标准流程引擎  | 预置节点：深化设计 → 进度管理 → 采购 → 到货验收 → 终验（模板可配） |
| 流程灵活可调  | 项目负责人可修改、排序、增减节点（biz_project_milestone） |
| 岗位职责显性化 | 每节点绑定责任人，到期未完成自动提醒，延期标红                 |
| 进度自动汇报  | 项目周报自动汇总节点进展，推送市场部与总办                   |
| MCP 支持  | proj.milestone_update：对话式更新/查询项目节点      |

**用户故事**：作为项目经理，我在 WorkBuddy 说「更新 XX 项目深化设计进度为已完成」，系统记录并同步看板；说「导出项目周进度」，收到周进度文件。

**验收标准**：节点变更留痕（操作人/时间）；延期自动标红并提醒责任人；项目周报自动包含我负责的项目。

## 7.7 产品中心（P1）

**核心命题**：招投标文档合规检查与方案智能生成。

**方案落点**

| 场景              | 实现                                                             |
| --------------- | -------------------------------------------------------------- |
| 招投标合规性对话式检查     | WorkBuddy 多轮引导，对照需求书逐项排查资质/参数/格式偏差，输出整改清单（kb.bid_check），标注依据出处 |
| 辅助生成实施方案/安装调试方案 | 结合需求书与投喂资料自动成稿，标注参考出处及链接                                       |
| 售前资料库           | 方案模板、案例、资质文件统一归档，生成时自动引用（FR-06）                                |

**用户故事**：作为售前工程师，我上传投标文件和需求书，说「检查这份投标文件合规性」，得到逐项整改清单；说「根据需求书生成安装调试方案」，得到带出处标注的初稿。

**验收标准**：合规检查输出可逐条追溯到需求书条款；生成文档出处链接可点击核对原文。

## 7.8 客服部（P1）

**核心命题**：客户问题收集、解决与原因分析。

**方案落点**

| 场景      | 实现                                |
| ------- | --------------------------------- |
| 问题登记自动化 | 对话式登记，自动分类、去重（dedupe_hash）、关联历史工单 |
| 辅助排查    | 接入客户系统知识库，检索排查原因并给出处理建议，向「自动回复」演进 |
| 问题归因分析  | 定期统计高频问题与根因，输出改善建议报告              |

**演进路线**：辅助人工回复 → 高频问题知识库自动回复 → 常见问题自动应答（二期）。

**用户故事**：作为客服，我说「登记客户 XX 反馈：打印机无法连接」，系统自动分类登记并给出相似历史工单与排查建议；每月我收到高频问题归因报告。

**验收标准**：登记对话 ≤ 1min 完成；相似工单推荐准确（按同类设备+症状）；归因报告含 Top10 高频问题与建议。

# 8. Mock 策略与外部集成开发指南

## 8.1 设计原则

外部依赖（企微、柠檬云、银行流水、税务文件）在凭证到位前**不阻塞开发**：全部抽象为数据源适配器接口，Mock 实现与真实实现可一键切换；接口契约以本章为准冻结。

## 8.2 数据源模式

```
DATA_SOURCE_MODE = mock | live        # 全局模式
DATA_SOURCE_OVERRIDES = wecom:live    # 可按数据源覆盖（如柠檬云仍 mock）
```

- `mock`：所有外部数据源返回种子数据（scripts/seed_mock.py 生成 3 个月量级演示数据，与方案 06 节示意看板同量级）；
- `live`：走真实 API/文件；
- 企微回调在 mock 模式下提供 `POST /api/v1/dev/mock/wecom-callback` 模拟审批事件；
- 模式仅对 `integration` 层生效，业务代码无感知。

## 8.3 适配器接口契约（Python Protocol）

```python
class WeComProvider(Protocol):
    def get_addressbook(self) -> list[DeptDto]: ...
    def get_approval_list(self, start: datetime, end: datetime) -> list[ApprovalDto]: ...

    def send_app_message(self, user_ids: list[str], content: MessageDto) -> SendResult: ...
    def get_journal_records(self, period: str) -> list[JournalDto]: ...
    def exchange_user_info(self, code: str) -> UserDto: ...

class LemonCloudProvider(Protocol):
    def fetch_vouchers(self, date_range: DateRange) -> list[VoucherDto]: ...

    def fetch_cash_journal(self, date_range: DateRange) -> list[CashJournalDto]: ...

class BankFlowProvider(Protocol):
```

# 10. API 设计规范

- 基础路径 `/api/v1`；REST 资源命名复数小写连字符（`/biz-contracts`）。
- 认证：`Authorization: Bearer <jwt>`；MCP 走独立 Token。
- 统一响应包：

```json
{ "code": 0, "message": "ok", "data": {}, "trace_id": "..." }
```

- 错误码：`0` 成功；`4xx00` 段业务错误（如 `40101` 未登录、`40301` 无权限、`40901` 重复登记）；`5xx00` 服务错误。
- 分页：`page`/`page_size`，响应含 `total`；列表默认按 `updated_at desc`。
- 时间：ISO 8601（东八区）；金额：decimal 字符串，单位元。
- 导出类接口走异步任务 + COS 链接，避免长阻塞。
- OpenAPI 文档由 FastAPI 自动生成（`/docs`，生产关闭）。

| 维度      | 要求                                                                   |

## 12.2 环境与发布

- `.env` 分层：基础配置入库（`.env.example`），密钥仅线上注入；
- 发布：`docker compose build && up -d`，Alembic 自动迁移前置校验；
- 灰度：单机场景下以「夜间发布 + 冒烟脚本」代替灰度；
- 监控：腾讯云可观测平台 CPU/内存/磁盘/可用性告警 → 企微应用消息推送管理员；业务侧关键任务失败（sync_job_log status=failed）同样告警。
