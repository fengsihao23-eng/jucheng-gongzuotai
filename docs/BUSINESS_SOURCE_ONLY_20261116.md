# 经营模块固定来源与看板汇总

合同台账、回款台账、商机信息、招标与在建，统一使用已绑定的企微工作簿 `signed-contract-ledger`。在线原表是唯一输入；历史导入、审批、人工台账的记录仍保留在原数据库供原财务流程追溯，但不进入这四个页面或看板对应的四块统计。

经营看板保留原 `Board.vue` 卡片、图表、月度历史、对比、晨报、目标配置、大屏和下钻。看板通过 `workbook_metrics` 汇总四个模块共用的来源明细，不把看板改成工作簿表格。按用户确认，重点项目、周报提交率、项目利润及其他原有业务区继续汇总各自模块。

## 数据规则

2026-11-17 更新经营业绩口径：页面默认2026年，按年、月筛选。2026年只使用“2026年销售合同”，2025年及更早年份只使用“2026年前（已签单个项目+未回款）”，按表内签订日期归集；长效合同、已签已回款和与中移项目不进入经营业绩。缺少日期的记录保留在“未注明日期”。看板签约、年度对比、月度历史和下钻共用这一口径；其他模块继续使用各自已确认的来源范围。

经营业绩使用紧凑业务筛选栏，去掉来源子表切换和整表原字段切换。区域、客户、负责人等筛选只取当年指定来源的原值；原表没有业务线或合同状态时禁用相应筛选并提示，不读取历史台账补齐。管理员的同步状态与来源操作权限继续保留。

项目列表恢复业务台账列与点击详情：合同编号、名称/客户、金额、签订日期、回款进度等；不再把单元格审阅作为正常项目入口。详情的名称、客户、负责人、金额、已收、未收、日期和区域始终沿用当前来源，不用旧台账覆盖。已有合同资料按已核验的工作簿身份只读关联，并沿用原合同/项目权限；身份不唯一或未关联时，仍可查看当前项目的基本信息、备注和附件。查看、刷新和返回详情不会新增/改写合同、回款、计划或来源对应关系。

“回款情况”默认合并“2026年销售合同”和“2026年前（已签单个项目+未回款）”，不按签订年份切分余额，显示全部金额和未收金额，主清单保留非零未收及待核对记录。累计已收不在页面展示。本月与本周合同金额移至经营业绩，仍按签订日期截至今天（周一为周起点）。看板的实际回款下钻采用到账日期和已核对金额，独立于签订合同金额。

回款页的“当月回款金额”和“次月回款金额”分别取当月预计可回款金额、次月达回款条件应回款金额列，与各子表总计核对一致才显示合计。卡片打开当月对应项目的小清单，可进入合同和项目反馈报告。合并计划按锚点计一次，各合同继续列示，不均分、不另造金额；原表未提供的月份不沿用过去年份的列。计划、人工进度和实际到账始终分开，两张表缺失其一时不展示合并合计。

回款跟进记录单独存放。有催办权限的人可发给一位在职公司账号；原表负责人唯一匹配时预填。发布要求后排队投递站内和企业微信通知，链接仅打开该事项及该合同信息。只有指定跟进人可填写进度、下一步安排和预计回款日；首次回复后可继续按“联系沟通、付款审批、等待付款、需协调、回款反馈待核对”追加记录，每次通知发起人。历史记录只追加并检查提交前版本，已反馈回款也不改动原表或登记到账。事项按签约记录身份识别，源表移行后仍可查询；没有台账权限的回复人仅看本人的事项和该合同。

2026-11-18 用户确认历史子表序号7—17的11个项目仅将12笔红字计入回款情况的合同总金额。口径按来源、项目和签约主体单独保存，其他15笔黑字不计入本模块合同金额；原表、未收、已收、实际到账、月度计划以及经营业绩口径保持。行号移动和金额更新仍按已选主体识别，新增或无法唯一识别的同项目主体标为待核对。清洗配置、前后合计和用户确认均记录审计。

- 完整来源版本原子替换，源行新增、改名、移行、删除都在下次同步反映。旧行不会因曾经导入而继续显示。
- 合同保留缺日期、零金额、文字金额、框架合同；期间签约按源表实际签订日期筛选，缺日期不编造，缺金额不补零。看板下钻使用同样的日期过滤和全部合同子表。
- 回款余额直接展示源表已收、未收，不从历史到账补数，不用合同金额倒算未收。合并金额只计锚点一次。
- 月度回款只读取有明确月份的“回款进度”列，年份来自销售子表标题。明确已完成的回款须与该列原表合计一致才供看板汇总。预计、待付、可能回款不算到账；其他月份留空。看板月度回款可下钻到回款情况中的实际回款清单。
- 商机信息只取「5、市场商机」。工单状态、责任人、联系人选项来自该子表；本周、本月新增取原表发起时间。列表和导出共用筛选，详情展示原表工单信息。原表未提供的金额、销售阶段与赢单统计不在商机信息页展示。
- “招标项目”和“在建项目”在同页分开切换，沿用原有两张子表。招标按合并项目展示一张卡片，项目详情保留各标段，金额包含每个标段。“在建项目”展示原表的已建设或已中标待签；原表无施工节点或回款进度时不展示对应指标。
- 展示原表公式结果的精度（招标金额存在三位小数），汇总不提前四舍五入。原表自身差异保留提示。
- 原有演示回款目标不自动沿用；原目标配置入口可重新填写，保存后看板立即采用并记录审计。

## 同步与回退

服务器每分钟检查版本，未变只检查版本；页面每 30 秒读取模块数据。获取过程校验前后版本，拒绝截断、不完整或无权限读取。已知表头变化时保留上次完整版本并显示失败原因。原表从不被写入。

`business_workbook.primary` 配置锁定唯一工作簿及文档 ID；启用后来源缺失、权限不足不会回退到混合台账。`presentation_only` 保证旧补齐合同与收款入账路径不再对本来源写入财务数据。重新保存绑定配置不会意外关闭此限制。

激活前全量备份数据库、文件和旧应用镜像。运行：

```bash
python -m scripts.activate_business_workbook signed-contract-ledger --docid <已核验文档ID> --revision <已核验版本>
python -m scripts.activate_business_workbook signed-contract-ledger --docid <已核验文档ID> --revision <已核验版本> --apply
python -m scripts.contract_workbook run signed-contract-ledger --force
```

激活脚本核验固定文档、版本和源表合计，记录配置前后审计。不做全库清空、种子重建或物理删除。应用回退使用发布备份中的镜像和前端；配置前值可从激活审计和数据库备份恢复。

验收覆盖：原表字段与合计、拆分标段、合并金额防重、空值和文字金额、增删改和移行、失败保留旧版本、权限隔离、看板与模块下钻一致、保留其他模块看板功能、桌面及手机、自动刷新与旧行详情失效。
