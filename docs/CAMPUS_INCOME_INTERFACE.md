# 校园每日营收预留接口

本接口按 2026-11-16 用户补充“预留接口”实现，当前没有绑定或定时抓取任何外部营收系统。已有文件导入和手工登记继续使用。接口与页面共用学校日汇总、权限、核对、防重和审计服务，不新增另一套收入台账。

## 鉴权与数据口径

- 使用现有工作台登录凭证：`Authorization: Bearer <已授权工作台会话令牌>`。接入账号必须有 `operations` 菜单，且能管理目标运营项目。未配置独立公共密钥或匿名入口。
- `project_id` 是运营项目 ID，`school_id` 必须是该项目已建档学校的真实 ID。不能传学校名猜测匹配。`school_id: null` 表示明确未分摊到学校的项目公共收入。
- 一所学校、一个实际收款日期只有一条日合计；同批多个同校同日条目会报错，请先在源系统合计。同一项目公共收入同日也是一条日合计。
- 金额单位元，使用最多两位小数的非负数；零是明确的零收入。未知/未获取不要提交零。实际收款日期用 `YYYY-MM-DD`，不得晚于北京时间当天。
- 此接口不做订单、学生个人信息、付款卡号、发票或复式记账。退款/手续费口径须由业务确认后由接入方形成适合日汇总的正确数据；不要将其猜测为负收入。
- 每批 1～1500 行；转换为标准收入数据后沿用 3MB 上限。整个批次核验通过才写入，任一差异均阻止批次写入。

## 1. 预览

`POST /api/v1/operations/{project_id}/income-feed/preview`

```json
{
  "source_key": "campus-payments",
  "batch_key": "2026-11-16-revision-1",
  "rows": [
    {
      "school_id": 123,
      "income_date": "2026-11-15",
      "amount": "125.50",
      "note": "已按实际收款日核对的日合计"
    }
  ]
}
```

示例 ID 仅说明格式，不应直接使用。先从获授权的项目详情读取真实学校 ID。

统一响应的 `data` 包含：

| 字段 | 含义 |
|---|---|
| `sha256` | 此来源、批次及正文的指纹，确认时必须原样提供 |
| `new_rows` / `new_amount` | 拟新增的日汇总数量/金额 |
| `unchanged` | 既有同校同日同金额条目数量，不再累计 |
| `error_count` / `errors` | 无效日期、未知学校、重复日、已有不同金额等差异 |
| `sample` | 用于核对的标准化样例 |
| `already_imported` | 该来源批次是否已确认；为真时返回原批次 `result` |

预览不写业务数据。错误或差异未处理时不能确认。

## 2. 确认

`POST /api/v1/operations/{project_id}/income-feed/confirm`

提交完全相同的 `source_key`、`batch_key`、`rows`，增加 `expected_sha256`：

```json
{
  "source_key": "campus-payments",
  "batch_key": "2026-11-16-revision-1",
  "rows": [
    {
      "school_id": 123,
      "income_date": "2026-11-15",
      "amount": "125.50",
      "note": "已按实际收款日核对的日合计"
    }
  ],
  "expected_sha256": "预览返回的64位十六进制指纹"
}
```

成功响应：`data.already_imported` 与 `data.result`。结果沿用收入导入回执，包含新增学校日数量、项目公共日数量、导入批次及金额等信息。调用方应核对实际回执，不能仅凭 HTTP 请求已发出认定入账。

## 重试、并发及更正

- `(project_id, source_key, batch_key)` 唯一；相同正文重试返回原回执，不再累计。
- 同一个批次编号但正文不同：HTTP 409，保留原记录。
- 改用新批次但同校同日已有不同金额：预览列差异，确认返回 409，不覆盖原账。
- 预览后其他人新增或更正了对应日汇总：确认时重新核对，必要时返回 409，重新预览。
- 不同来源重复传入同校同日同金额：视为已有，不加一次收入。
- 需要更正已登记金额时，在原收入记录按既有权限核对更正，不能靠换批次覆盖。
- 403 为权限不足，404 为项目不可见/不存在，400 为字段或内容校验失败，409 为版本/差异冲突。均沿用 `{code,message,data,trace_id}` 响应。

## 页面核验

项目 → 每日收入，查看本年/本月/本周/今日卡片、区域、明细和接入状态。历史年仅显示明确的年度期间。公共收入不分摊进某个学校区域。最后登记日期是最近已有收款记录的日期，不表示源系统已完整更新到当天。

“已接收接口批次”仅表示发生过成功接口写入，并不宣称已开通持续自动采集。具体源系统、刷新周期、签名认证/服务账号生命周期将在实际对接时确定。
