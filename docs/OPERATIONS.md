# 运营项目跟进（智慧校园试点）

会议需求对应的入口为侧栏「市场与项目 → 运营项目」，路径 `/operations`。

## 使用流程

1. 董事长、市场经理或平台管理员新建运营项目，填写负责人、分类、本阶段目标及目标日期，可标记为重点项目。
2. 在「项目团队」加入跨部门参与人员，设置项目管理员、执行成员或只读成员；有管理权限的人也可以从这里打开「项目设置」。
3. 公司任务点击「布置任务」，指定负责人、截止日期、计划月份、完成要求及反馈频率；可以关联学校，并拆成多个阶段节点。本人计划从「月度任务 → 自行安排」进入，选择不同的部门审核人、公司审核人，提交两级审核后生效。
4. 执行成员点开任务，在独立弹页选择「已完成」或「未完成」，填写结果或当前进度，勾选本次完成的节点后提交。未完成时保留已有进度值，可标记受阻；受阻或逾期须写明原因。手机端用全屏弹页，关闭后回到原列表和筛选。
5. 管理者查看最新进展、下一步、逾期与受阻事项；在「当前需要做什么」集中查看待办，或使用「进度记录 → 进展汇总」「问小聚」。任务安排、转交及每次反馈均留痕。

项目负责人或有管理权限的成员可在项目首页点击「填写项目进度」，分别填写进度情况、遇到的问题、下一步计划。有下一步计划须同时给出计划完成日期。项目首页与「进展汇总」显示最近一次填写的内容，「进度记录」可回看历史。项目进度填写不会改变单项任务的完成情况；项目详情可以通过「用小聚填写」把要求带入对话。

任务负责人必须为本项目负责人、项目管理员、部门审核人或执行成员。普通成员只能反馈自己的任务；管理者可代为反馈，但记录保留真实操作人。任务完成前必须确认全部节点。仍有未完成任务的成员，需要先转交任务才能移除或降为只读；仍有待审核任务的部门审核人也须先调整审核人。更换项目负责人时，原负责人保留执行成员身份，便于完成交接。

## 月度计划闭环

「运营项目 → 月度任务总表」跨项目查看，「项目详情 → 月度任务」查看该项目。按计划月份、负责人和任务来源筛选，显示具体事项、完成情况、未完成原因及下一步；待审核和已退回任务单独标明，不计入有效任务。顶部统计跟随当前筛选。

月度完成率、状态分布及明细使用同一组任务。「任务情况」按「进行中」「已完成」分组；待开始、受阻、待审核和已退回均归入「进行中」，卡片仍显示各自状态和节点。点击卡片或明细可打开任务详情。「月度任务」没有当月事项时会提示已有任务的其他计划月份。网页或小聚保存后同步刷新同浏览器页面；其他会话打开的运营页面约 12 秒检查一次，返回标签也会刷新。任务反馈期间如果别人已更新，保留当前输入，核对最新版本后再提交。

任务只有一条记录：创建时默认以截止月份作为计划月份，也可显式指定；单独延长截止日期保留原计划月份。未完成任务在后续月份继续显示为跨月事项；完成后保留在原计划月及延续到实际完成月的视图中。该视图显示当前状态，不伪称月末历史快照。

自行安排只能由项目执行成员为本人提交。部门审核人由项目团队中的负责人、项目管理员或明确授予「部门审核人」角色的成员担任。公司审核人需要 `operations:approve`，默认董事长 / 总经理（ZB-01）和平台管理员具备。两位审核人及提交人须不同；管理员也不能代替另一位指定审核人点击审核。

部门审核通过后进入公司审核，公司通过后进入负责人月度执行任务。退回保留意见，提交人可调整后重新提交；修改自拟任务会重新触发两级审核。审核绑定任务版本，重复、过期或跳级审核被拒绝。审核、退回、转交和进展反馈都有站内通知及操作记录。受阻或逾期仍未完成时必须填写未完成原因。

小聚可直接查询月度表、布置公司任务、提交自拟计划、按本人权限审核和反馈。聊天中的「确认执行」确认当前用户的具体业务动作，不代替或跳过两级审核。WorkBuddy 的 `ops.project_status` 支持 month / owner_id，`ops.task_create`、`ops.task_review`、`ops.task_feedback` 共用业务权限和校验。

真实模型验收使用独立测试库、合成项目和四个不同角色，已走通「老板查询并派单 → 自拟计划提交 → 部门审核 → 公司审核 → 本人反馈完成 → 老板对话查询月度结果」，所有写入核对数据库回执。另有浏览器验收覆盖页面提交、两级审核、完成反馈和手机布局。未在生产库创建测试任务或向真实人员发送测试通知。

验收脚本为 `acceptance/operations-agent.mjs`（真实 Pi + 已配置模型）和 `acceptance/operations-monthly.mjs`（多角色浏览器）。后端用独立 `TEST_DB` 运行 `tests/test_operations_monthly.py` 及原运营、导入、小聚、MCP 和平台回归，合计 80 项通过。真实模型使用 deepseek-flash 完成六轮业务操作与最终月度查询，多角色页面与手机布局验收通过。数据库迁移 `d30a72fb619e` 为已有任务按截止月份补计划月，保留为已生效的公司安排；新增审核权限和两个 MCP 工具。

## 学校、设备及收入

- 「学校与经营资料」维护学校、拓展阶段、意向程度、下一步及跟进日期；学校详情可查看阶段变更历史和关联任务的反馈。
- 「设备产品库」维护产品名称、品牌、型号、单位和参考价格。学校设备清单可复用本人有权限查看的运营项目中的产品。
- 各学校建设投入优先采用已填写的原表清单金额，否则为 `数量 × 实际采购单价`；合计再加人工及其他投入。单价支持六位小数，未知价格留空，并显示未标价数量。产品参考价后续变化不会改写已登记的采购单价。清单金额与计算金额不同须填写核对说明；利旧、共用、拆回、调拨等保留来源备注，历史建设数量不代表当前在用库存。
- 各学校每日收入采用“一所学校、一个日期、一条合计”口径；重复登记会提示编辑原记录。可补录历史收入，不允许未来日期和负数。
- 展示各学校及项目的投入、累计登记收入和每日收入趋势。这些收入和投入不替代财务利润报表。
- 无法归属学校的实收列入项目公共收入，不虚构学校。项目合计包含学校与公共收入，按日期只汇总一次。

本次提供手工维护功能，未执行公司资料导入。仓库库存、采购系统对接、企业微信消息联动、自动方案生成保持后续阶段范围。

## 项目授权和提醒

所有登录人员可看到运营项目入口，但只读到本人负责或加入的项目。拥有 `operations:manage` 的公司管理者及平台管理员可管理全部运营项目。此范围独立于其他模块的部门 / 全公司数据范围，财务人员不会仅因财务数据权限而获得所有运营项目的访问权。

默认 `ZB-01`（董事长）和 `SC-01`（市场经理）获得 `operations:manage`。数据库迁移仅为这两个角色已有的按钮配置追加该权限，其他配置保留；无库内按钮覆盖的角色继续使用代码默认值。真实账号及项目成员由现有管理员按实际名单配置。

发布和转交任务会产生站内通知；提交进展会通知项目负责人和仍有访问权的发布者。系统任务 `operations_task_reminder` 每日北京时间 16:00 检查进行中项目，提醒今日到期、逾期、受阻或今日尚未按日反馈的任务负责人，逾期 / 受阻同时提醒项目负责人。同一任务、同一人员每天不重复产生提醒。已完成或已暂停项目不产生待办提醒。

## 小聚与 WorkBuddy

小聚的业务目录包含运营项目查询、任务安排和反馈、团队、学校跟进、产品、设备及收入操作。检索“运营项目”“智慧校园”“重点任务”“产品库”即可找到。业务写入沿用小聚已有的具体执行单确认机制，并在实际提交时重新校验项目权限。

示例：

- “智慧校园项目进展怎么样？有哪些逾期和受阻任务？”
- “把学校需求确认安排给项目团队中的张三，周五前完成，分需求确认和方案提交两个节点。”
- “我负责的学校对接已完成一半，校方明天确认方案，请帮我整理反馈。”

WorkBuddy 新增 `ops.project_status` 和 `ops.task_feedback`，共享相同的服务层及权限。先查询项目 / 任务取得真实 ID，再反馈；工具不能跳过节点校验或读取未授权项目。新增工具通过 Alembic 迁移登记，保留平台原有启停与调用审计。

“进展汇总”根据数据库事实直接生成；“AI 整理文字”调用现有模型配置，模型不可用时保留原文，并在页面提示。测试验证了业务目录、执行单、权限和 MCP 协议调用，未使用真实模型或真实企业微信发送消息。

## 经过核对的数据快照导入

后续导入支持未标价、精确单价、原表金额、核对备注，以及无学校归属的项目公共实收。迁移 `c92fd610b8a4` 扩展金额字段并建立 `ops_import_batch`、`ops_project_income`。保留原清单金额时不擅自分摊折扣或改写数量。

操作脚本 `scripts.import_operations_snapshot` 读取经过核对的 JSON 清单，复用项目权限、校验及审计服务。文件 SHA-256 与项目组成唯一键；原文件重复执行不会重复导入。学校设备已有记录或收款日期冲突时停止，整个事务回滚，不覆盖人工数据。脚本默认预演回滚，只有 `--apply` 才提交。必须先在隔离库核对完整清单的数量与金额。

```bash

python -m scripts.import_operations_snapshot /private/reviewed-manifest.json --project-id 1 --operator-id 42 --apply
```

以上 ID 仅为调用形式，实际执行前须核对线上项目和获授权操作账号。源文件和含业务数据的清单位于 Git 忽略目录 `var/`；订单按学校与实际支付日期汇总，不把学生姓名、账号或订单个人信息上传到运营模块。支付平台复制映射表不能重复计入，后台记账但缺少外部支付记录的条目列为待核对。
