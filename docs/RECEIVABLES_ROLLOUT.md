# 聚成工作台：合同业绩、开票与收款一期

## 工作方式

工作台业务库是统计来源。合同审批直接登记合同台账；财务历史资料和企微固定表统一先进入来源核对队列。企微表是可选输入，不需要把审批写一份表再导入一遍。此版本不回写企业微信表格。

- 合同：同合同号、客户、金额以及有提供时的签订日相符，审批只挂接旧台账；冲突进审批登记队列。业绩使用 `sign_date`，新审批提供真实签订日时优先采用，旧模板沿用原日期规则。历史合同可继续走现有合同清洗导入。
- 开票：批准的开票申请进入待确认。财务确认实际发票号码、日期和金额后入账；原票、累计红冲和更正原因可核对。审批变化后，已开票金额不会自动改；待开票申请在复核前不能继续确认。
- 到账：由财务确认，或由指定的财务到账审批在最终通过后触发。每笔实际到账使用同一唯一凭证号。合同回款复用原台账，其他及待匹配到账单列。关联旧回款时填写合同详情中的回款 ID，不会再新增回款。
- 核销：一笔到账可分配给多张发票，发票也可分多次收款。合同收款按同合同匹配；非合同收款只匹配相同客户且未关联合同的票。本期一笔合同到账只关联一个合同。
- 更正：撤销新到账会移除该笔产生的合同回款并重新计算应收计划；撤销引用旧回款的记录只解除其关联和发票核销，旧回款仍保留。如确属旧账登记错误，按原流水核对或导入流程撤回。原到账凭证号保留在撤销记录上，经过财务核对后可用明确的更正凭证号重新登记，并备注原记录。
- 看板：按开票月展示当前有效开票额，按实际到账日展示收款；已开票未收和应收计划逾期是当前余额，不是历史月末余额。银行自动获取和会计凭证生成不在本期。
- 小聚：具有台账查看权限的账号可以查询汇总、开票、到账和核销明细，仍走工作台权限。

## 角色

董事长可查看台账和看板；会计可确认开票；出纳可确认到账和核销；财务经理可做上述操作、办理更正、核对历史来源。平台管理员负责企业微信授权、模板配置和审批变更复核。已定制角色需要在「系统管理 → 角色权限」显式加入 `receivables` 菜单及所需的 `receivables:invoice`、`receivables:receipt`、`receivables:correct`、`receivables:source` 权限。公司专用读取账号可以只授固定资料接入所需权限和可见范围，按现有个人中心连接企业微信。

## 配置真实审批

使用公司企业微信应用的审批读取及回调权限。在「系统管理 → 字典与口径」增加 `approval_template` 字典项，键为该企业实际模板 ID，`fields` 的左边是审批控件显示名，右边是系统字段名。下面为示例，左侧标题以实际模板为准。

合同审批：

```json
{"key":"contract","require_contract_no":true,"fields":{"合同编号":"contract_no","合同名称":"name","客户名称":"customer_name","合同金额":"amount","正式签订日":"sign_date","业务线":"business_line","所属项目":"project_code"}}
```

开票申请：

```json
{"key":"invoice","fields":{"客户":"customer","开票金额":"amount","合同编号":"contract_no","备注":"note"}}
```

财务到账确认：

```json
{"key":"receipt","fields":{"到账凭证号":"reference","实际到账日":"received_on","金额":"amount","付款方":"payer","收款账户简称":"account","收款类型":"kind","合同编号":"contract_no","已有回款ID":"payment_id","备注":"note"}}
```

`kind` 可用 `contract`、`unmatched`、`other`，也可用表单选项“合同回款”“待匹配收款”“其他收款”。只绑定已包含财务实际到账核实环节的审批模板。模板映射错误或记录冲突在「系统管理 → 审批登记」核对。已登记后发生撤回或字段变化时，先按业务记录办理更正，再由管理员标记已核对，原业务不会再次登记。

## 首次历史导入与固定来源

1. 财务确认历史范围和截止日，整理有效发票及真实到账记录。没有实际到账日期的期初余额不能用导入当天替代。
2. 「财务 → 开票与收款 → 来源核对」下载开票或到账 CSV 模板，按 UTF-8 上传。日期用 `YYYY-MM-DD`；号码、凭证号及合同编号保持文本；金额单位元；表中只保留业务明细。每批最多 1,000 行、2 MB。
3. 核对来源字段后勾选入账。已由合同台账登记的到账请填 `payment_id`。发票历史入账后，可在到账明细中逐笔核销，核对各发票剩余金额。已有未核销的历史收款不会被自动猜测为某张发票的回款。
4. 核对合同业绩、发票净额、累计到账及余额，固定切换日。以上均先在隔离环境或只读试运行中核实。

持续同步可在字典 `receivables_source` 中新增数据源项，例如键 `finance-receipts`：

```json
{
  "enabled": true,
  "auto_apply": false,
  "reader_id": 123,
  "format": "smartsheet",
  "kind": "receipt",
  "docid": "实际文档ID",
  "sheet_id": "实际子表ID",
  "fields": {
    "reference": "到账凭证号",
    "received_on": "实际到账日",
    "amount": "到账金额",
    "payer": "付款方",
    "account": "收款账户简称",
    "kind": "收款类型",
    "contract_no": "合同编号",
    "payment_id": "已有回款ID"
  }
}
```

`reader_id` 为工作台账号数字 ID。`format` 可以是 `smartsheet` 或 `sheet`；在线表格第一行为字段名，业务凭证号须为文本。字段列表可参照 CSV 模板，未在实际表里存在的可选列不要配置。开票来源把 `kind` 设为 `invoice`，映射发票号码、日期、金额、客户及可选字段。每个来源最多 1,000 行。微盘二进制 Excel 文件可先转 CSV 作历史导入，或整理到已授权的固定在线子表。

任务 `receivables_source_sync` 每 15 分钟执行，可从「系统管理 → 定时任务」手动试跑。默认只暂存。确认源表只含财务确认后的实际数据且对账无误，再将该源 `auto_apply` 设为 `true`。源行变更、删除或授权失败不会覆盖正式记录；源表已入账后有变动，财务按正式台账办理更正。需停用来源时把 `enabled` 设为 `false`。

## 上线与验收

1. 备份生产库后随版本执行 `alembic upgrade head`，包含区域业绩迁移 `f2a6c8d1b4e7` 和本期 `7b4d928e51a0`。按正常流程构建前端、重启服务；测试用 `scripts.seed` 不可在业务库运行。
2. 在公司实际租户用一份合同审批、一份开票申请和一笔真实或隔离试单分别验证授权、回调、字段及统计。同步来源先关自动入账，手动试跑核对返回行。两套入口若处理同一笔业务必须使用相同发票号码或到账凭证号。
3. 验证历史查重、部分到账、分配、撤回、红冲、权限隔离、恢复补拉和看板下钻，再启用自动入账。需暂停时可停用相应字典项和源配置，保留已确认数据供核对。
4. 自动化由服务端调度运行，配置不依赖开发人员电脑。公司设备的选购及生产迁移按现有部署方案另行安排。

自动验收：`backend/tests/test_receivables.py` 覆盖合同匹配与统计、审批撤回、部分核销、收款防重、历史入账和来源变更；`acceptance/receivables.mjs` 仅对本机隔离 Mock 服务运行，验证浏览器操作和看板下钻。
