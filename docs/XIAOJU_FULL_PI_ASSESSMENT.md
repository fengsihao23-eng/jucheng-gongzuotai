# 小聚接入完整 Pi 的可行性评估

评估日期：2026-10-23

实施记录：本评估后的升级实现见 [完整 Pi 运行说明](XIAOJU_FULL_PI.md)。下文的现状与离线验证为实施前记录。

## 结论

可以接入完整 Pi，现有 Vue + FastAPI + Node 架构没有阻断条件。建议使用官方 `@earendil-works/pi-coding-agent@1.3.0` SDK，复用现有 Python 业务执行器、账号权限、执行单和回执。

这是一次中等规模的运行时与会话改造。安装完整 SDK 后，还要配置资源加载、内置扩展、工具和网页交互，才能实际获得相应能力。

本评估中，“完整 Pi”指完整会话运行时、上下文压缩、Skills、扩展、提示模板、MCP、模型与思考设置，以及文件和命令执行工具。模型实际的推理、视觉等能力取决于所选模型。企业微信、财务等系统仍需各自的工具接入与真实授权。

## 已核对的现状

- Node 入口只使用 `pi-agent-core` 与 `pi-ai`，版本均为 1.3.0；同版本完整 SDK 已发布，内部依赖与现有核心一致。
- 当前固定 `thinkingLevel: off`、单次模型响应最多 1800 token、每任务最多 20 轮；Python 另限制 300 秒与 64 次工具调用。这些是当前应用配置，并非 Pi 的固定限制。
- 每次任务启动新的 Node 子进程；前端上传最近 12 条纯文本历史，没有完整的服务端 Pi 会话。跨任务恢复主要依靠业务回执和执行单。
- 已有 Python 业务执行器会再次校验账号、记录权限和参数；重要写入通过本人确认；已有去重、快照检查与回执。上述逻辑可以复用。
- Node 子进程目前与 API 同容器运行，工作目录为后端，并默认继承 API 的环境变量。开放任意文件读写和 Shell 时必须调整这一部署结构。
- Docker 已安装 Node，且有 `/data` 持久化卷。无需为基本 SDK 集成更换后端语言或数据库。

原 Pi 的终端界面不能直接变成网页组件。依赖终端弹窗或自定义终端界面的扩展，需要提供网页交互适配；不能据此承诺所有第三方扩展零修改兼容。

## 建议实现方式

1. **完整 SDK 管理会话。** 按 `账号 / 会话` 存储 Pi 会话，浏览器只发送新消息和会话 ID。新对话不再依赖客户端回传历史或关键词判断“继续”。现有任务回执可保留，旧聊天没有存下的原文无法补回。
2. **复用现有业务执行器。** SDK 工具通过现有 JSONL 桥调用 Python。Python 继续负责权限、凭证与业务提交；待确认工具返回终止信号，确认完成后向同一会话注入可核验回执再继续。
3. **加载完整资源与扩展。** 公司维护通用业务 Skills，员工配置按账号保存。显式加载 MCP、Codemode 与工具搜索，避免“安装了 SDK，相关功能却没有启用”。
4. **隔离文件与命令执行。** 为执行任务提供独立容器或等效隔离环境，分开工作目录、配置目录和会话目录；执行环境不继承 API 的数据库口令和企业密钥，不挂载后端配置。仅设置不同 `cwd` 不构成文件或进程权限隔离。
5. **网页补齐交互。** 展示流式回答、工具进度、历史会话与文件结果；支持停止、执行中补充需求和断线恢复。
6. **限制改为任务预算。** 输出长度、轮数和超时按任务配置，结合自动压缩和明确的中断状态，避免长任务无声截断。

初期仍可按任务启动 Node 并打开持久会话文件；无需立即引入常驻 Node 服务。相同会话必须串行执行，防止多个 FastAPI worker 同时修改会话。需要更高并发或执行中持续交互时，再采用专门的运行服务与队列。

## 主要工程难点

- **多人隔离：** 独立目录不足以隔离任意 Shell；需要运行环境和凭证边界。当前 API 容器不适合直接向员工开放原生 Shell。
- **历史权限变化：** 完整会话会保存工具响应。角色或记录权限变化时，需要清理或失效相关模型上下文，不能只隐藏界面卡片。
- **业务确认恢复：** 确认前必须停止依赖该写入的步骤；确认后回到原会话核对回执，保持幂等与取消语义。
- **运行成本：** 更长上下文、思考、压缩与脚本执行会增加 token、耗时和内存开销；没有负载数据前不能给出可靠的服务器容量或费用数字。
- **网页扩展兼容：** SDK 接口可用不代表终端扩展的交互已经完成网页适配。

## 已完成的兼容性验证

在仓库外的临时目录安装官方 `pi-coding-agent@1.3.0`，使用独立配置目录、工作目录和会话目录，设置 `PI_OFFLINE=1`。探针正常退出，结果如下：

- 完整 SDK 可导入并创建会话；本地验证 Node 为 v26.8.1，包声明要求 Node >=22.19.0。
- 可识别 DeepSeek Flash 模型元数据并设置 `thinkingLevel: high`；没有发送真实模型请求。
- Skills、提示模板和项目上下文可以发现。
- 自定义扩展能接收到会话启动事件。
- 原生 `read / bash / edit / write`、Codemode、工具搜索和自定义业务桥工具可以同时注册。
- 自定义工具可执行并保留 `terminate` 标志；此项仅验证适配接口，没有经过真实模型工具循环。
- 完整消息可保存到会话文件，销毁会话后重新打开并恢复。
- 压缩、停止、steer 和 followUp 接口存在；本次没有调用模型执行压缩摘要。

**验证范围：** 以上证明同版本 SDK 的基础集成可行。尚未进行 Linux 生产镜像验证、真实模型长对话与压缩、外部 MCP 握手、执行隔离或业务迁移回归。本评估没有修改应用运行代码，也没有操作业务数据库。

## 工作量估算与验收

按一名熟悉现有项目的开发者、单站点部署、复用现有业务工具估算：

- 可用验证版：约 2–3 个工作日，覆盖完整 SDK、持久会话、资源加载与业务工具桥。
- 上线版本：总计约 1–2 周，加入执行隔离、流式交互、确认恢复、权限变化处理和回归。

这是基于代码范围的粗估，需由第一阶段迁移结果修正。新增企业系统、桌面连接器、新工具及外部授权等待时间另计。

上线应至少验证：跨刷新和重启恢复、长上下文压缩、两名员工之间的文件与会话隔离、权限变更后历史数据不可再用、确认前无写入与确认后不重复执行、取消与超时状态、产物下载权限，以及 Linux 镜像中的真实模型和既有业务流程。
