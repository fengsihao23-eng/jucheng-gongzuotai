# 经理资料接入：使用与验收

修订日期：2026-10-30。此文对应经理资料接入修复版；部署时需一起更新前后端，实际运行版本以 `/health` 的 `revision` 为准。

## 给经理的使用说明

1. 打开「资料导入」，先填写可选的用途说明，再拖入多个文件或一个 zip。
2. 原件保存后，页面显示「识别中」，可离开后回来查看；看「识别详情」核对摘要、分类依据、表头和样例。
3. 文档确认分类与可见范围。默认本部门，无部门默认仅本人；全员共享必须明确选择。有明确分类的多份文档可勾选后「按建议提交」，提交前会列出每份的分类与范围。
4. 表格若匹配合同、商机、回款或项目台账，具有 `clean:import` 和清洗菜单权限的人核对字段后导入。其他经理不因此自动获得记账权限，资料交给授权整理人代办。多工作表文件必须确认本次导入的工作表。
5. 不符合台账模板的参考表格可由上传人自行改为知识库资料，不必永久卡在待整理池。识别错误时原件仍保留，可重新识别或请整理人协助。
6. 关注最终状态：知识资料只有「已发布」才参与检索；业务数据按实际成功导入的行数进入原台账及已有统计。小聚可查询资料处理进度，但不会替用户批准共享或导入。

## 隔离规则

- 上传原件：本人、平台管理员，以及在授权范围内接手或处理待整理池的整理人可访问。普通整理人不能浏览别人尚未转交的原件。
- 整理范围：`imports:handle` 决定能否整理，`data_scope=self/dept/all` 限制范围。全公司整理权限是明确的特权，不应随意授予所有经理。
- 清洗任务：只开放本人或授权整理范围内的任务；知道任务编号不能查看、改映射、取消、导入或下载他人的清洗报告。
- 知识文档：默认本部门，也可选择仅本人、指定角色或全员。分类审核人在审核阶段能处理内容，知识库管理员有管理权限，不等于所有经理能查看。
- 原件及历史版本下载：需本人登录，下载时重新检查权限。仅复制签名链接不能绕过权限；文档缩小共享范围后旧链接同样受限。
- 代办：知识文档归原上传人，不归点击提交的整理人。审核通知、进度查询与撤回仍能找到原上传人。

## 本次修复

- 原件下载及清洗任务访问权限复核；待整理池与通知采用实际角色授权和部门范围。
- 默认部门/本人可见；受限重复文件不泄漏其他部门的标题、编号或存在性。
- 文档引用链接使用落库后的真实 ID，修复首次上传的 `doc=None` 链接。
- 后台识别、失败保留原件、超时重试、批量核对提交及明确的待审核/驳回/部分入库状态。
- 台账提交时重新查重，多工作表明确选择，零有效记录拒绝导入，超限不静默截断。
- 受限文档的分块统计按权限过滤；发布审核回执不额外赋予审核人阅读权限。
- 小聚目录增加资料进度和处理能力；共享、导入、撤回等变更仍需本人确认。
- 小聚业务摘要明确提示截断，长知识文档提供带权限检查的分块分页；上传资料使用「工作台资料」来源标签，不受外部连接的 mock 标签误导。
- 图片和扫描版 PDF 改用多模态大模型逐页识别（不用传统 OCR）：识别全文可查看、正文缓存后确认入库不重复调用模型；管理员能直接处理同事待整理池里的扫描件，长任务转后台，不再卡住请求超时。新增「待我处理」页签，集中列出其他同事已识别完、等待确认的资料。
- 同步调整企业微信「我的导入进度」，不再将待审核文档笼统显示为已入库。

## 仍需明确的边界

这不是「任何数据一上传就自动建看板」。当前自动写台账仍只有合同、商机、回款、项目四类；工资、花名册、库存等需要相应业务模型和权限设计。一般参考表格可以入知识库，但这不等于结构化台账或财务口径已验证。

图片、扫描版 PDF 现在由多模态模型逐页转录，标注「扫描识别」，入库前必须对照原件核对金额、编号、日期和签章页；单份最多 30 页，超限先拆分。旧版 doc/xls/ppt 仍需要转换。模型分类仅用部分正文样例，是可修改建议；不能保证所有复杂文件自动分类正确。中文检索目前仍是 BM25 与同义词规则，没有引入向量检索。

知识材料由经理核实真实性、时效性和共享范围，分类审核人审核后发布。已有文档的共享范围不会被这次代码更新自动修改。

后台识别状态与原件持久化，执行使用应用进程；重启中断后可重试，但尚未引入持久化作业队列。zip 最多 100 个条目、解压后 200MB，单原件最多 50MB；台账清洗最多 20MB。部署时前后端必须一起更新，以支持鉴权下载。

## 验证方法

本次验证结果：全量后端 391 项通过（含 8 项扫描件/图片识别与管理员待办回归），前端生产构建通过。扫描件识别用合成合同图片在本地 DeepSeek 与生产 ctaigw 网关各跑通一次，模型返回的合同编号、金额与图片一致；没有把真实业务资料作为模型测试输入。浏览器 14 项来自上一版资料接入验收，本次未重跑。

所有测试必须使用独立数据库和临时存储，禁止对实际业务库执行种子或验收脚本。

```sh
cd backend
TEST_DB=jucheng_test_intake_20261030_full .venv/bin/python -m pytest tests -q
cd ../frontend
VITE_OUT_DIR=/tmp/jucheng-intake-build-20261030 npm run build
```

浏览器测试脚本：`acceptance/manager-intake.mjs`。要求独立测试 API `127.0.0.1:18100`，前端 `127.0.0.1:15180`，API 必须返回 `env=test, mode=mock`。脚本真实上传合成资料、提交审核、核验隔离、下载原件、导入一条合成合同并检查手机布局。默认截图在 `/tmp/jucheng-intake-evidence-20261030/`，不进入仓库。

真实模型分类使用单独的合成交换机巡检文本验证，没有向模型提交真实员工、客户或业务文件。分类返回「客服 / 运维规范」，并生成正确标题与摘要；该验证不等同于所有文件格式或真实业务语料均已验收。
